2.2 ddrive: Forward Kinematics¶

Package download

Download ddrive.zip

ddrive is a two-node "turtlesim, but you built it" package. One node holds a pose and integrates it with a hand-written Euler integrator; the other node visualizes it.

Node Owns Subscribes Publishes
ddrive_sim the pose [x, y, theta], the integrator /cmd_vel (geometry_msgs/Twist) /pose (geometry_msgs/Pose2D)
ddrive_viz nothing — just draws /pose — (opens a matplotlib window)

ddrive_sim works fine with nobody ever publishing to /cmd_vel — it just holds still at its initial pose and keeps publishing that pose every dt seconds. That's what makes the staged workflow below possible: you can see the system before you drive it.

0. Install the package¶

mkdir -p ~/ros2_ws/src
cp -r ddrive ~/ros2_ws/src/
cd ~/ros2_ws
source /opt/ros/$ROS_DISTRO/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --packages-select ddrive
source install/setup.bash

Checkpoint:

ros2 pkg executables ddrive

should list exactly two: ddrive ddrive_sim and ddrive ddrive_viz.

1. What's in the package¶

ddrive/
├── package.xml          # name, dependencies (rclpy, geometry_msgs), build type
├── setup.py             # registers the two executables below
├── setup.cfg
├── resource/ddrive       # marker file ament needs to find the package
├── config/
│   └── params.yaml       # default parameters for both nodes
├── launch/
│   └── ddrive_launch.py  # brings sim + viz up together
└── ddrive/
    ├── __init__.py
    ├── kinematics.py     # pure Python, no ROS import — the Euler integrator
    ├── sim_node.py       # ddrive_sim
    └── viz_node.py       # ddrive_viz

kinematics.py is deliberately ROS-free. It's the same math as the original diff_drive_fk.py script's euler_integration() function, just refactored into a euler_step(z, u, dt) function:

def euler_step(z, u, dt):
    x0, y0, theta0 = z
    v, omega = u

    xdot = v * math.cos(theta0)
    ydot = v * math.sin(theta0)
    thetadot = omega

    x1 = x0 + xdot * dt
    y1 = y0 + ydot * dt
    theta1 = theta0 + thetadot * dt
    return [x1, y1, theta1]

sim_node.py wraps that in ROS: a subscriber updates the commanded [v, omega] whenever /cmd_vel arrives, and a separate timer calls euler_step every dt seconds using whatever the latest command was:

def _cmd_vel_cb(self, msg: Twist):
    self._u = [msg.linear.x, msg.angular.z]        # just caches it

def _step(self):                                    # runs every dt seconds
    self._z = euler_step(self._z, self._u, self._dt)
    ...publish self._z as Pose2D on 'pose'...

There's no loop connecting these two — rclpy.spin()'s executor calls whichever callback is ready (a new message, or the timer firing) and that's the whole "cycle."

viz_node.py subscribes to /pose and redraws on every message, same circle-plus-heading-line drawing as the original script's animate(), just triggered by messages instead of a precomputed array.

2. Run it¶

Stage 1 — pose, no motion (2 terminals)¶

Terminal 1:

source /opt/ros/$ROS_DISTRO/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 run ddrive ddrive_sim

Override the initial pose to prove it's a real parameter, not hard-coded:

ros2 run ddrive ddrive_sim --ros-args -p x0:=1.0 -p y0:=-0.5 -p theta0:=1.5708

Terminal 2:

source /opt/ros/$ROS_DISTRO/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 run ddrive ddrive_viz

A matplotlib window opens with the robot sitting still at whatever pose you set in Terminal 1.

Stage 2 — command it (3rd terminal)¶

Keep Terminals 1–2 running.

Terminal 3:

source /opt/ros/$ROS_DISTRO/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.3}, angular: {z: 0.2}}" -r 10

Watch the plot window — the robot curves immediately. Ctrl+C, then stop it properly (it keeps the last command it received otherwise):

ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}" -1

When you Ctrl+C ddrive_viz, it saves the trail to ddrive_trajectory.png in its working directory.

Stage 3 — collapse into a launch file¶

ros2 launch ddrive ddrive_launch.py

Same two nodes, one command. Overridable arguments:

ros2 launch ddrive ddrive_launch.py x0:=1.0 theta0:=1.5708 dt:=0.05 robot_radius:=0.3

3. Look at the graph — nodes and topics¶

With sim + viz running:

ros2 node list
ros2 node info /ddrive_sim
ros2 topic list
ros2 topic info /cmd_vel --verbose
ros2 topic echo /pose
ros2 topic hz /pose

node info on /ddrive_sim shows it subscribing to /cmd_vel and publishing /pose. If rqt_graph is installed, this draws the same picture live:

rqt_graph

4. Change how fast it moves¶

Any of these on /cmd_vel changes the motion in real time (with ddrive_sim + ddrive_viz running):

# straight line
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5}}" -r 10

# spin in place
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{angular: {z: 1.0}}" -r 10

# arc
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.4}, angular: {z: 0.5}}" -r 10

-r 10 repeats at 10 Hz; -1 publishes once and exits.

5. Parameters — more than one way to set them¶

Using robot_radius (a ddrive_viz parameter) as the running example:

Code default, in viz_node.py:

self.declare_parameter('robot_radius', 0.1)

CLI override at startup:

ros2 run ddrive ddrive_viz --ros-args -p robot_radius:=0.2

YAML file (config/params.yaml, installed to the package share dir):

ddrive_viz:
  ros__parameters:
    robot_radius: 0.2
    axis_limit: 2.0
    save_path: ddrive_trajectory.png

ros2 run ddrive ddrive_viz --ros-args --params-file \
  ~/ros2_ws/install/ddrive/share/ddrive/config/params.yaml

Launch argument:

ros2 launch ddrive ddrive_launch.py robot_radius:=0.3

Live, while the node is running — this needs the node to register a callback, or ros2 param set silently changes the stored value without changing behavior:

self.add_on_set_parameters_callback(self._on_param_change)

def _on_param_change(self, params):
    for p in params:
        if p.name == 'robot_radius':
            self._R = p.value
        # ...
    return SetParametersResult(successful=True)

ros2 param get /ddrive_viz robot_radius
ros2 param set /ddrive_viz robot_radius 0.4

ddrive_viz has this callback wired up, so the circle resizes on the next redraw. ddrive_sim's dt does not have one — try ros2 param set /ddrive_sim dt 0.02 and notice the timer's rate doesn't actually change. Worth demonstrating both, back to back.

6. What's next¶

ddrive_ik builds directly on top of this package — same ddrive_sim and ddrive_viz, unmodified, with two new nodes added to close a tracking control loop. See the next page.

ddrive_sim also now has a ResetPose service — see Part 3 of the ddrive_ik_msgs page for the server code, the terminal client, and how to call it.
