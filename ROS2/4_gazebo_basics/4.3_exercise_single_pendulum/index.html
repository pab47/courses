4.3 Exercise: Single Pendulum Swing-Up¶

Build a single pendulum — one link, one revolute joint — in Gazebo, and drive it from hanging at rest up to the inverted (upright) equilibrium using the same feedback-linearization / computed-torque approach as dbpendulum_ctrl, just with one degree of freedom instead of two.

The model¶

A single pendulum's equation of motion is the one-link special case of dbpendulum's dynamics — no coupling term between links, because there's only one link:

M(theta) * thetaddot + C(theta, thetadot) + G(theta) = T

with, for a single rigid link of mass m, moment of inertia I about its own center of mass, and pivot-to-COM distance c:

M(theta) = I + m*c^2        # constant — no theta dependence for 1 DOF
C(theta, thetadot) = 0       # no Coriolis/centrifugal term with only 1 joint
G(theta) = m*g*c*sin(theta)  # gravity torque, same functional form as dbpendulum's G1/G2

Two equilibria fall out of G(theta) = 0: theta = 0 (hanging down, stable) and theta = pi (inverted, unstable) — same logic dbpendulum's design notes walk through for the passive double pendulum's initial condition, just here you're driving the system to the unstable one on purpose, rather than starting near it.

What to build¶

Two packages, mirroring the dbpendulum / dbpendulum_ctrl split:

single_pendulum — passive, visual-only sanity check first:

single_pendulum/
├── urdf/
│   └── single_pendulum.urdf.xacro
├── config/
│   └── single_pendulum_params.yaml   # m, I, c, l
├── worlds/
│   └── single_pendulum_world.sdf
├── launch/
│   └── single_pendulum.launch.py
└── config/
    └── single_pendulum_bridge.yaml

single_pendulum_ctrl — the actuated version:

single_pendulum_ctrl/
├── urdf/
│   └── single_pendulum.urdf.xacro     # own copy — add <ros2_control> block
├── config/
│   ├── single_pendulum_ctrl_params.yaml   # m, I, c, l, g, kp, kd
│   └── controllers.yaml                    # joint_state_broadcaster + effort_controller
├── launch/
│   └── single_pendulum_ctrl.launch.py
└── single_pendulum_ctrl/
    ├── dynamics.py       # M(theta), G(theta) closed-form
    ├── trajectory.py     # theta_ref(t): 0 -> pi
    └── control_node.py    # computed-torque law, publishes to effort_controller

Suggested steps¶

  1. Passive version first. Get single_pendulum swinging freely under gravity before adding any control — same staged approach as dbpendulum. Confirm it hangs at theta = 0 at rest, and that a small push away from theta = 0 produces a normal pendulum swing.
  2. Design the reference trajectory. Pick a theta_ref(t) that goes smoothly from 0 to pi over some duration — a simple option is a single smooth point-to-point move (cubic or quintic polynomial in time), the single-joint analog of the two segments dbpendulum_ctrl uses for its two links.
  3. Implement the control law. Same structure as dbpendulum_ctrl's controller, minus the coupling terms: 
    T = M(theta) * (thetaddot_ref - Kp*(theta - theta_ref) - Kd*(thetadot - thetadot_ref)) + G(theta)
    Pick Kp/Kd critically damped, same convention as dbpendulum_ctrl: kd = 2*sqrt(kp).
  4. Match gravity to Gazebo's default (9.8, not 9.81 or 10) — dbpendulum_ctrl's design notes explain why this has to match exactly for feedback linearization to actually cancel gravity.
  5. Wire up ros2_control. Same pattern as dbpendulum_ctrl: joint_state_broadcaster for state feedback, forward_command_controller/ForwardCommandController (interface effort) as a pass-through for your computed torque — the actual control law lives in your node, not in a canned controller.
  6. Set the <ros2_control> initial_value to match your trajectory's theta(0) = 0 — if these don't match, expect the same "snaps hard the instant control starts" failure mode dbpendulum_ctrl's troubleshooting section describes.

Verify¶

  • Log the tracking error (theta - theta_ref) over the run and confirm it stays small throughout, not just at the final instant — a controller that overshoots wildly and only happens to end near pi hasn't actually demonstrated tracking.
  • Once it reaches theta = pi, it needs to stay there — since that equilibrium is unstable, this is really the point of the whole exercise: watch what happens if you cut the trajectory node before the tracking error has settled, versus after.

Deliverables¶

  • [ ] single_pendulum swinging passively under gravity
  • [ ] single_pendulum_ctrl driving the joint from 0 to pi
  • [ ] A plot or log showing tracking error settling near zero and staying there once theta_ref reaches pi
  • [ ] A short note on what Kp/Kd you used and how you chose them
