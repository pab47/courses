3.3 Exercise: threelink_ik¶

Extend twolink_ik to a three-link planar arm. The new wrinkle: you're no longer just solving for a target position — you're also solving for the end-effector's orientation.

The model¶

For a two-link planar arm, twolink_ik solves 2 equations (x_ref, y_ref) for 2 unknowns (theta1, theta2) — exactly determined.

Add a third link and the forward kinematics becomes:

x = l1*cos(theta1) + l2*cos(theta1+theta2) + l3*cos(theta1+theta2+theta3)
y = l1*sin(theta1) + l2*sin(theta1+theta2) + l3*sin(theta1+theta2+theta3)
phi = theta1 + theta2 + theta3

phi — the end-effector's orientation relative to the world x-axis — falls out for free from a serial planar chain: it's just the sum of all the joint angles. That gives you a third equation, which is exactly what you need for a third unknown: with 3 links you now solve 3 equations (x_ref, y_ref, phi_ref) for 3 unknowns (theta1, theta2, theta3) — still exactly determined, same as twolink_ik was with 2 and 2.

For this exercise, fix the target orientation at:

phi_ref = 90°  (pi/2 rad) — end effector pointing straight up

What to build¶

Mirror the twolink_ik package structure:

threelink_ik/
├── urdf/
│   └── threelink.urdf.xacro      # joint1, joint2, joint3; l1, l2, l3 as xacro args
├── config/
│   └── threelink_ik_params.yaml   # l1, l2, l3, x_ref, y_ref, phi_ref
├── launch/
│   └── threelink_ik.launch.py     # robot_state_publisher + ik_node + rviz
├── rviz/
│   └── threelink_ik.rviz
└── threelink_ik/
    ├── kinematics.py              # forward_kinematics() + inverse_kinematics()
    └── ik_node.py                  # loads l1, l2, l3, x_ref, y_ref, phi_ref -> solves once -> publishes /joint_states

Suggested steps¶

  1. Extend the URDF. Add a third revolute joint and link, same pattern as joint1/joint2 in twolink's xacro — just chained one further.
  2. Extend forward_kinematics(). Add the l3/theta3 terms to x, y, and add the new phi = theta1 + theta2 + theta3 output.
  3. Extend the fsolve residual. twolink_ik's residual function returns [x - x_ref, y - y_ref]; yours needs a third entry, [x - x_ref, y - y_ref, phi - phi_ref], and fsolve now solves for [theta1, theta2, theta3] instead of [theta1, theta2].
  4. Set the target in config/threelink_ik_params.yaml: 
    /**:
  ros__parameters:
    l1: 1.0
    l2: 1.0
    l3: 0.5
    x_ref: 0.8
    y_ref: 0.8
    phi_ref: 1.5708   # 90 degrees, in radians
  5. Verify with tf2, same trick as twolink_ik: 
    ros2 run tf2_ros tf2_echo base_link end_effector
    The translation should match (x_ref, y_ref, 0) — but this time, also check the rotation. end_effector's frame should show a rotation of phi_ref about Z.

Things worth thinking about¶

  • With phi_ref fixed, does every (x_ref, y_ref) you try actually have a solution? (Hint: think about the arm's total reach, and what configurations can hold the end effector vertical while still reaching a given point — not every point in the two-link arm's reachable set is still reachable once orientation is constrained.)
  • fsolve needs an initial guess. If it fails to converge or lands on a physically odd (e.g. self-intersecting) configuration, try a different starting guess — same lesson as any nonlinear solver, just more visible with a third joint added.

Deliverables¶

  • [ ] threelink.urdf.xacro with three working revolute joints
  • [ ] kinematics.py with forward_kinematics() returning (x, y, phi) and inverse_kinematics() solving all three joint angles
  • [ ] ik_node.py publishing /joint_states so RViz shows the arm reaching (x_ref, y_ref) with the end effector vertical
  • [ ] tf2 check confirming both position and orientation match target
