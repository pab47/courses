Installation¶

This site uses Docker on every host OS — Ubuntu, macOS, and Windows — instead of installing ROS 2 directly on your machine. The reason is version control: your host OS might not match a given ROS 2 release (Ubuntu 20.04 can't run Jazzy natively, for example), but a Docker image gives you exactly the ROS 2 distro you want, independent of what your host is running.

Every command on this site sources ROS 2 via $ROS_DISTRO instead of a hardcoded name like foxy or jazzy, so the exact same commands work no matter which distro's image you're running. You'll set this once inside the container, in 1.3:

source /opt/ros/$ROS_DISTRO/setup.bash

and, once you've built at least one package:

source ~/ros2_ws/install/setup.bash

1.1 Install Docker¶

Pick your host OS below. All three converge on the same checkpoint: a working docker command.

Ubuntu (or any Linux host)¶

Docker Engine installs directly — no VM layer needed:

sudo apt update && sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io
sudo usermod -aG docker $USER

Log out and back in (or reboot) so your user picks up the docker group, then confirm:

docker run hello-world

macOS¶

Install Docker Desktop for Mac — download the .dmg, drag it into Applications, and launch it once to finish setup.

Apple Silicon (M1/M2/M3/M4)

If you're on an Apple Silicon Mac, you'll confirm you're pulling a native arm64 image later, in 1.2 — an emulated (x86_64) image runs noticeably slower. This check does not apply to Intel Macs, which only ever pull native x86_64 images.

Confirm Docker is working:

docker run hello-world

Windows¶

Docker Desktop on Windows needs WSL2 (Windows Subsystem for Linux) as its backend — which conveniently also gives you a real Ubuntu shell, so every bash command on this site works unmodified.

  1. Open PowerShell as Administrator and run: 
    wsl --install
    Reboot when prompted. This installs WSL2 and a default Ubuntu distro.
  2. Install Docker Desktop for Windows. During setup, make sure "Use WSL 2 based engine" is checked (this is the default on modern installs).
  3. In Docker Desktop, go to Settings → Resources → WSL Integration and enable integration with your Ubuntu distro. Restart Docker Desktop.
  4. Open the Ubuntu app from the Start Menu — this is your WSL2 terminal.

Run every command on this site from the Ubuntu (WSL2) terminal

Not PowerShell, not Command Prompt. From here on, ~/ros2_ws means your WSL2 Ubuntu home directory, and every command on this site behaves exactly as written for Mac/Linux.

From the Ubuntu terminal, confirm Docker is reachable:

docker run hello-world

1.2 Pull the image and create the container¶

docker pull tiryoh/ros2-desktop-vnc:jazzy

Swap jazzy for whichever ROS 2 distro you want — check available tags at hub.docker.com/r/tiryoh/ros2-desktop-vnc/tags. Whatever you pick here is also what you'll set $ROS_DISTRO to in 1.3 — keep the two in sync.

Apple Silicon: confirm it's native arm64

docker image inspect tiryoh/ros2-desktop-vnc:jazzy | grep Architecture
should print "Architecture": "arm64".

Create a folder that will become your ROS 2 workspace, then start the container:

mkdir -p ~/ros2_ws/src
docker run -d --name ros2_jazzy \
  --shm-size=512m \
  -p 6080:80 \
  -v ~/ros2_ws:/home/ubuntu/ros2_ws \
  -e VNC_PASSWORD=ubuntu \
  tiryoh/ros2-desktop-vnc:jazzy

Naming the container ros2_jazzy (rather than after any one package) keeps it obvious which ROS 2 distro it's running — rename it to match if you pull a different distro's image, e.g. ros2_humble.

Log into the Ubuntu desktop¶

Open http://localhost:6080 in a browser. You'll land on a VNC password prompt — enter ubuntu (the password set above). You should land on a full Ubuntu desktop with a terminal on the taskbar. Everything else on this site — every ros2 run, every colcon build — happens in terminals opened from that desktop, not in your host OS's own terminal.

Where ~/ros2_ws actually lives¶

The -v ~/ros2_ws:/home/ubuntu/ros2_ws flag maps one real folder on your host to a path inside the container:

On your host Inside the container
~/ros2_ws (Mac/Linux), or your WSL2 Ubuntu ~/ros2_ws (Windows) /home/ubuntu/ros2_ws

The container's user is ubuntu, whose home directory is /home/ubuntu — so /home/ubuntu/ros2_ws is also just ~/ros2_ws from a terminal inside the container. In other words, ~/ros2_ws means the exact same folder whether you type it on your host or in a VNC desktop terminal — they're not two copies, they're one folder viewed from two places. Anything you colcon build inside the container (build/, install/, log/) is written straight onto your host's disk, and any file you drop into ~/ros2_ws on your host shows up instantly inside the container.

This is also why your workspace survives even if you delete the container entirely — the folder was never inside the container to begin with.

Everyday startup (after the first time)¶

You only need to docker run once. After that:

docker start ros2_jazzy
then back to http://localhost:6080. Whatever you installed inside the container earlier — including the optional matplotlib/numpy setup below — is still there, since docker start reuses the same container rather than creating a new one.

To stop it when you're done for the day: 

docker stop ros2_jazzy

If you ever need to start completely fresh (wipes anything installed inside the container, but never touches ~/ros2_ws on your host): 

docker rm -f ros2_jazzy
# then re-run the docker run command above

1.3 Set $ROS_DISTRO and verify ROS 2 works¶

Inside the container's desktop terminal:

echo 'export ROS_DISTRO=jazzy' >> ~/.bashrc   # match whatever distro you pulled in 1.2
source ~/.bashrc
echo $ROS_DISTRO

That last line should print your distro name back. From now on, every terminal on this site starts the same way:

source /opt/ros/$ROS_DISTRO/setup.bash

Verify: talker / listener¶

The real test that ROS 2 is alive isn't that the commands exist — it's that two independent nodes can actually publish and subscribe to each other. Open two terminals inside the container's desktop.

Terminal 1: 

source /opt/ros/$ROS_DISTRO/setup.bash
ros2 run demo_nodes_cpp talker

Terminal 2: 

source /opt/ros/$ROS_DISTRO/setup.bash
ros2 run demo_nodes_py listener

Terminal 1 should print Publishing: 'Hello World: N' once a second, and Terminal 2 should print I heard: [Hello World: N] right behind it. Ctrl+C both once you've seen it work.

Once you've built at least one workspace package (starting on the next page), every terminal also needs:

source ~/ros2_ws/install/setup.bash

matplotlib/numpy (only if a node needs them)¶

Not every package on this site needs these — install them inside the container only when a node actually imports them (e.g. ddrive's visualizer node):

pip3 install matplotlib numpy --break-system-packages

NumPy/matplotlib version mismatch

On newer Ubuntu/ROS combinations, a pip-installed NumPy 2.x can conflict with an apt-installed matplotlib built against NumPy 1.x, causing an ImportError when a node imports matplotlib. If you hit this, either pin NumPy down: 

pip3 install "numpy<2" --break-system-packages --force-reinstall
or use apt for both instead of pip: 
sudo apt install -y python3-matplotlib python3-numpy
